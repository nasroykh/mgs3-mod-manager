## Failures resolved before publication

The first attempts did not publish. Diagnostics exposed an expected negative installer test leaking its last native exit code, hosted TEMP using an 8.3 alias rejected by strict path validation, and parent-directory DELETE_CHILD rights defeating a file-only DELETE-denial fixture. Windows permits deletion with either file DELETE or parent DELETE_CHILD rights ([Microsoft documentation](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-deletefile)).

The workflow now isolates the test process, uses a canonical temporary path, and configures both scratch trees (`work/test-temp` and `.cache/winfs-tests`). Production guards and all tests remain enabled. The exact ACL failure was reproduced locally by granting parent DELETE_CHILD in a new fixture tree, then the full filesystem suite passed after denying that alternate route. An earlier reproduction attempt could not change the pre-existing cache ACL; a subsequent quoted test-flag correction was necessary before the exact reproduction succeeded.

Local evidence: `work/verify-public-release.ps1`, `work/asi-loader-verification/v0.1.0-public-install.log`, and `work/public-release-06aabe6475314cb88a23417718511659/`. These ignored files are local evidence; the public workflow and release remain independently accessible.
